## 1. 제품 개요

### 1.1 한 줄 정의

> **누구나 쉽게 모든 모임을 만들고 참여하는 지도 기반 모임 앱**

### 1.2 문제 정의

모임을 만들고 참여하는 과정이 단톡방, 에브리타임, 지도 앱 등으로 분산되어 있다. 근처에서 열리는 모임을 한눈에 보기 어렵고, 친구와 합류·조율도 별도 채널에 의존한다.

momo는 **지도 위에서 모임을 보고·만들고·참여**하며, **친구와 함께 모임을 조율**할 수 있게 한다.

### 1.3 핵심 가치

| 순위 | 가치 | 설명 |
| --- | --- | --- |
| 1 | 발견 | 지도에서 근처 공개 모임을 한눈에 본다 |
| 2 | 생성 | 종류별 폼으로 모임을 빠르게 만든다 |
| 3 | 연결 | 모임에 가입하거나, 친구 위치·초대·합류 현황으로 함께 모인다 |

### 1.4 성공 지표 (KPI)

| 지표 | 설명 |
| --- | --- |
| 가입 완료율 | 가입 시작 → 가입 완료 전환율 |
| 주간 모임 생성 수 | 활성 사용자당 주간 모임 생성 건수 |
| 모임 참여 수 | 모임 참여·합류 건수 |
| 친구 연결 수 | 친구 관계 수립 건수 |

### 1.5 MVP 범위

| 포함 | 미포함 (Out of Scope) |
| --- | --- |
| 회원가입·로그인 | 결제·유료 모임 |
| 메인 지도 + 내 위치 | 외부 SNS 로그인 (카카오/구글 등) |
| 모임 4종 (택시·스터디·스포츠·밥약) | 친구 1:1 DM |
| 친구 관리·위치 공유 | 실시간 음성/영상 |
| 모임 전용 채팅·합류 현황 | 데이트/소개팅 모임 (2차) |
| AI 근처 추천·생성 초안 | |

### 1.6 팀 구성

| 이름 | 역할 | 담당 영역 |
| --- | --- | --- |
| 이승민 | UI/UX | 화면 설계 |
| 정우영 | 기획,디자인 / 프론트엔드 | 기획서,디자인시스템 / Flutter UI |
| 김동준 | 백엔드 | API, DB, 인프라 |
| 김건희 | AI | 추천·생성 보조 |

## 2. 타겟 사용자

### 2.1 타겟 레이어

| 레이어 | 대상 | 시점 | 제품 대응 |
| --- | --- | --- | --- |
| **L1 (MVP)** | 대학생 | 현재 | 카피·온보딩·기본 모임 종류를 대학생 맥락에 맞춤 |
| L2 | 취준생·직장 초년 | 이후 | 종류 추가(네트워킹·퇴근 후), 온보딩 문구 변경 |
| L3 | 지역 주민 | 이후 | 동네 단위, 생활 모임 |

- **가입 제한 없음** — 학교 메일·지역 제한 없이 아무 이메일로 가입 가능
- 확장 방법: 같은 앱·같은 계정, 온보딩에서 관심사 선택 → 기본 필터·추천 가중치만 변경

### 2.2 페르소나 (초안)

**페르소나 A — 대학생 지민 (22세)**

- 심야에 역까지 택시비가 부담되어 합승을 찾는다
- 시험 기간 도서관 스터디·운동 인원을 빠르게 모은다
- 친구 위치를 대략적으로 공유하며 만남을 조율한다

**페르소나 B — 대학생 현우 (24세)**

- 에브리타임·단톡 대신 지도에서 근처 모임을 탐색한다
- 모르는 사람과도 공개 모임에 참여하고, 마음에 드는 사람에게 친구 요청을 보낸다

## 3. 사용자 시나리오

### 3.1 S1. 신규 가입 → 메인

| 단계 | 화면 | 동작 | 상태 |
| --- | --- | --- | --- |
| 1 | 랜딩 | **시작하기** 탭 |  UI 완료 |
| 2 | 이메일 입력 | 유효 이메일 입력 → **계속** (`sendOtp`) |  Mock |
| 3 | OTP 입력 | 6자리 입력 → **확인** (`verifyOtp`) |  Mock |
| 4 | 비밀번호 설정 | PW·확인 일치 → **계속** |  UI 완료 |
| 5 | 생년월일 | 스크롤/타이핑 입력 (기본 2000-01-01) → **계속** |  UI 완료 |
| 6 | 닉네임 | 입력 → **중복 확인** → **가입 완료** |  Mock |
| 7 | 메인 | 가입 스택 제거 후 진입 |  플레이스홀더 |

-> 실 이메일 발송, `completeSignUp` API, 세션 저장

### 3.2 S2. 기존 회원 로그인

1. 랜딩 → **계정이 이미 있습니다**
2. 이메일 + 비밀번호 입력 → `login`
3. `AuthSession` 저장 → 메인 진입

**상태:** UI·API 연동 미구현

### 3.3 S3. 메인에서 모임 탐색·참여

1. 앱 실행 → 메인 지도 (내 위치 중심)
2. 지도 위 공개 모임 마커 확인 (종류별 아이콘·색상)
3. 상단 필터 칩으로 종류 선택 (전체 / 택시 / 스터디 / 스포츠 / 밥약)
4. 마커 탭 → 모임 상세 → 참여 요청
5. 참여 시 모임 스코프 위치 공유 동의 → 합류 현황 확인

### 3.4 S4. 모임 생성

1. 상단 **+** 탭 → 종류 선택 (택시 / 스터디 / 스포츠 / 밥약)
2. 공통 정보 입력 (제목, 집결 장소·시간, 인원)
3. 종류별 추가 정보 입력 (도착지 / 과목 / 종목 등)
4. (선택) 친구 초대, AI 제목·설명 초안
5. 생성 → 지도에 마커 표시 (기본 **전체 공개**)

### 3.5 S5. 친구 추가·위치 공유

**경로 A — 앱 밖 실제 친구**

1. 친구 탭 → 닉네임 검색 / 친구 코드 / QR
2. 친구 요청 → 수락 → 위치 공유 모드 설정 (정확 / 대략 / 안 함)

**경로 B — 모임에서 만남**

1. 공개 모임 참여 → 참여자 프로필에서 **친구 추가** (선택)
2. 모임 종료 후 "오늘 함께한 사람" 목록에서 친구 요청

**경로 C — 연락처 초대**

1. 친구 탭 → 연락처 권한 허용
2. 가입자: 친구 요청 / 미가입자: SMS·초대 링크 발송

### 3.6 S6. 모임 합류·조율

1. 모임 참여 → 모임 스코프 위치 공유 ON (기본 제안)
2. 모임 상세·복숭아 허브에서 참여자 합류 현황 확인 (`출발` / `이동 중` / `근처` / `도착`)
3. 모임 전용 그룹 채팅으로 조율 ("5분 늦어요" 등)
4. 모임 종료 → 모임용 위치 자동 OFF

### 3.7 예외 시나리오

| 상황 | 동작 |
| --- | --- |
| 이메일 형식 오류 | **계속** 버튼 비활성 |
| OTP 불일치 | `otp-invalid` → 빨간 테두리·문구·입력 초기화 |
| 닉네임 중복 | `nickname-taken` → 빨간 문구, **가입 완료** 비활성 |
| 위치 권한 거부 | 지도 중심 불가 → 권한 안내·재요청 |
| 네트워크 오류 | `network` 코드 → 재시도 안내 |
| 모임 정원 초과 | 참여 불가 안내 |
| 신고·차단 | 프로필·모임에서 신고 → 차단 시 상호 비노출 |

### 4.2 인증 기능 상세

#### F-002 sendOtp

| 항목 | 내용 |
| --- | --- |
| 입력 | `email`, `purpose` (`signUp` \| `changePassword` \| `findId`) |
| 반환 | OTP 만료 시각 |
| 정책 | 6자리, 5분 유효, 재전송 쿨다운 30초 |
| signUp | 미가입 이메일만 → 아니면 `email-already-used` |
| changePassword / findId | 가입 이메일만 → 아니면 `email-not-found` |

#### F-003 verifyOtp

| 항목 | 내용 |
| --- | --- |
| 입력 | `email`, `code` |
| 반환 | `VerificationToken` (1회성) |
| 실패 | `otp-invalid`, `otp-expired`, `otp-attempts` |

#### F-006 checkNicknameAvailability

| 항목 | 내용 |
| --- | --- |
| 입력 | `nickname` (2~10자) |
| 성공 | void |
| 실패 | `nickname-taken`, `nickname-policy` |

#### F-007 completeSignUp (추가 필요)

```
입력: verificationToken, email, password, birthDate, nickname
반환: AuthSession
```

### 4.4 위치·친구 기능 상세

#### 위치 공유 모드 (젠리식)

| 모드 | 상대에게 보이는 것 | 용도 |
| --- | --- | --- |
| `precise` | 실시간에 가까운 좌표·이동 | 합류 중, 택시 탑승 직전 |
| `approximate` | 동네/캠퍼스 단위 | 평소 친구에게 대략 공유 |
| `off` | 마커 없음 | 프라이버시 |

- 친구마다 모드를 다르게 설정 가능
- 기본값: `approximate` 권장

#### 모임 스코프 위치 공유

- 해당 `meetingId` 참여 중 + `recruiting`/`ongoing` 상태일 때만
- **같은 모임 참여자에게만** 노출 (친구 관계와 별개)
- 모임 종료 시 자동 OFF
- 참여 시 동의: "이 모임의 다른 참여자에게 합류용 위치가 공유됩니다."

#### 합류 현황 (`arrivalStatus`)

| 값 | 설명 |
| --- | --- |
| `not_started` | 아직 출발 안 함 |
| `on_the_way` | 이동 중 |
| `nearby` | 집결지 근처 |
| `arrived` | 도착 |

- 자동: 집결지까지 거리 기반 AI 계산
- 수동: "출발했어요" / "도착" 버튼 (위치 거부 시 대안)

#### 관계 모델

| 관계 | 설명 |
| --- | --- |
| 앱 사용자 | 가입자 |
| 친구 | 수락된 양방향 관계 + 위치 모드 |
| 모임 참여자 | 특정 모임에만 묶인 임시 관계 (종료 후 해제) |

**참여자 ≠ 자동 친구.** 모임 후 선택적 친구 추가.

## 8. 비즈니스 규칙·정책

| 항목 | 정책 |
| --- | --- |
| 로그인 | 이메일 + 비밀번호 |
| 이메일 | 아무 메일 허용 (학교 메일 제한 없음) |
| 비밀번호 | 영문+숫자 8~32자 (서버 재검증) |
| OTP | 6자리, 5분 유효, 재전송 30초 쿨다운 |
| 닉네임 | 2~10자, 유니크 |
| 생년월일 | 올해−100 ~ 올해, 유효한 날짜. 연령 확인·필터용 |
| 모임 기본 공개 | `public` 기본. friends/invite_only는 옵션 |
| 위치 공유 | 친구 모드 별도, 모임 스코프 별도. 모임 종료 시 자동 OFF |
| 친구 | 양방향 수락 필요. 모임 참여 ≠ 자동 친구 |
| 모임 채팅 | 모임 참여자만. 종료 후 N일 뒤 읽기 전용/삭제 |
| 안전 | 신고·차단 최소 기능. 실명 강제 없음 |
| 연락처 | 전화번호 해시 매칭 권장. 권한·고지 필수 |

원칙: 프론트 1차 검증 + **서버 동일 정책 재검증**.

### 확정된 제품 방향

- **정의:** 누구나 쉽게 모든 모임을 만들고 참여
- **발견:** 모임 기본 전체 공개. 친구 전용·초대만은 옵션
- **지도:** 4종 동시 표시, 상단 칩으로 종류 하나만 필터
- **위치:** 젠리식 모드. 모임 참여 중 합류용 위치 공유, 종료 시 OFF
- **친구:** (1) 원래 아는 사람—코드/연락처 (2) 모임에서 만남—선택 추가
- **모임:** 채팅 + 합류 현황. 참여자 ≠ 자동 친구
- **인증:** 이메일+비밀번호, 아무 메일, 생년월일 수집
- **AI:** 근처 추천 + 생성 초안
- **지도 SDK:** MVP Google Maps, 교체 가능
- **메인 UI:** + 모임 만들기 / 복숭아 허브 / 메뉴
- **대상:** 1차 대학생, 가입 제한 없음, 이후 레이어 확장
