## 1. 제품 개요

### 1.1 한 줄 정의

> **누구나 쉽게 모든 모임을 만들고 참여하는 지도 기반 모임 앱**

### 1.2 문제 정의

모임을 만들고 참여하는 과정이 단톡방, 에브리타임, 지도 앱 등으로 분산되어 있다. 근처에서 열리는 모임을 한눈에 보기 어렵고, 친구와 합류·조율도 별도 채널에 의존한다.

momo는 **지도 위에서 모임을 보고·만들고·참여**하며, **친구와 함께 모임을 조율**할 수 있게 한다.

### 1.3 핵심 가치

| 순위 | 가치 | 설명 |
| --- | --- | --- |
| 1 | 발견 | 지도에서 근처 공개 모임을 한눈에 본다 |
| 2 | 생성 | 종류별 폼으로 모임을 빠르게 만든다 |
| 3 | 연결 | 모임에 가입하거나, 친구 위치·초대·합류 현황으로 함께 모인다 |

### 1.4 성공 지표 (KPI)

| 지표 | 설명 |
| --- | --- |
| 가입 완료율 | 가입 시작 → 가입 완료 전환율 |
| 주간 모임 생성 수 | 활성 사용자당 주간 모임 생성 건수 |
| 모임 참여 수 | 모임 참여·합류 건수 |
| 친구 연결 수 | 친구 관계 수립 건수 |

### 1.5 MVP 범위

| 포함 | 미포함 (Out of Scope) |
| --- | --- |
| 회원가입·로그인 | 결제·유료 모임 |
| 메인 지도 + 내 위치 | 외부 SNS 로그인 (카카오/구글 등) |
| 모임 5종 분류(밥약·스포츠·스터디·택시·취미) | 친구 1:1 DM |
| 친구 관리·위치 공유 | 실시간 음성/영상 |
| 모임 전용 채팅·합류 현황 | 결제·유료 모임 |
| AI 근처 추천·생성 초안 | |

### 1.6 팀 구성

| 이름 | 역할 | 담당 영역 |
| --- | --- | --- |
| 이승민 | UI/UX | 화면 설계 |
| 정우영 | 기획,디자인 / 프론트엔드 | 기획서,디자인시스템 / Flutter UI |
| 김동준 | 백엔드 | API, DB, 인프라 |
| 김건희 | AI | 추천·생성 보조 |

## 2. 타겟 사용자

### 2.1 타겟 레이어

| 레이어 | 대상 | 시점 | 제품 대응 |
| --- | --- | --- | --- |
| **L1 (MVP)** | 대학생 | 현재 | 카피·온보딩·기본 모임 종류를 대학생 맥락에 맞춤 |
| L2 | 취준생·직장 초년 | 이후 | 종류 추가(네트워킹·퇴근 후), 온보딩 문구 변경 |
| L3 | 지역 주민 | 이후 | 동네 단위, 생활 모임 |

- **가입 제한 없음** — 학교 메일·지역 제한 없이 아무 이메일로 가입 가능
- 확장 방법: 같은 앱·같은 계정, 온보딩에서 관심사 선택 → 기본 필터·추천 가중치만 변경

### 2.2 페르소나 (초안)

**페르소나 A — 대학생 지민 (22세)**

- 심야에 역까지 택시비가 부담되어 합승을 찾는다
- 시험 기간 도서관 스터디·운동 인원을 빠르게 모은다
- 친구 위치를 대략적으로 공유하며 만남을 조율한다

**페르소나 B — 대학생 현우 (24세)**

- 에브리타임·단톡 대신 지도에서 근처 모임을 탐색한다
- 모르는 사람과도 공개 모임에 참여하고, 마음에 드는 사람에게 친구 요청을 보낸다

## 3. 사용자 시나리오

### 3.1 S1. 신규 가입 → 메인

| 단계 | 화면 | 동작 | 상태 |
| --- | --- | --- | --- |
| 1 | 랜딩 | **시작하기** 탭 |  UI 완료 |
| 2 | 이메일 입력 | 유효 이메일 입력 → **계속** (`sendOtp`) |  Mock |
| 3 | OTP 입력 | 6자리 입력 → **확인** (`verifyOtp`) |  Mock |
| 4 | 비밀번호 설정 | PW·확인 일치 → **계속** |  UI 완료 |
| 5 | 생년월일 | 스크롤/타이핑 입력 (기본 2000-01-01) → **계속** |  UI 완료 |
| 6 | 닉네임 | 입력 → **중복 확인** → **가입 완료** |  Mock |
| 7 | 온보딩 설문 | 선호·시간·중요도1~4·기피 (건너뛰기 허용) | 미구현 (AI/온보딩 구체화) |
| 8 | 메인 | 가입·온보딩 스택 제거 후 진입 |  플레이스홀더 |

-> 실 이메일 발송, `completeSignUp` API, 세션 저장, 온보딩 선호값 저장

### 3.2 S2. 기존 회원 로그인

1. 랜딩 → **계정이 이미 있습니다**
2. 이메일 + 비밀번호 입력 → `login`
3. `AuthSession` 저장 → 메인 진입

**상태:** UI·API 연동 미구현

### 3.3 S3. 메인에서 모임 탐색·참여 (카테고리 체계 추가, 마커/상세 UX 추가)

1. 앱 실행 → 메인 지도 (내 위치 중심)
2. 지도 위 공개 모임 마커 확인 (큰 틀 카테고리 아이콘·색상 + 온라인 전용 마커)
3. 상단 필터 칩으로 큰 틀 선택 (전체 / 밥약 / 스포츠 / 스터디 / 택시 / 취미)
4. 필요 시 세부 카테고리로 추가 필터링 (예: 스터디 > 자격증, 프로젝트)
5. 마커 1회 탭 → 모임 프리뷰 바텀시트 확인
6. 프리뷰의 **상세 보기** 탭 → 모임 상세 화면 진입
7. 참여 시 모임 스코프 위치 공유 동의 → 합류 현황 확인

### 3.4 S4. 모임 생성 (카테고리 체계 추가)

1. 상단 **+** 탭 → 큰 틀 카테고리 선택 (밥약 / 스포츠 / 스터디 / 택시 / 취미)
2. 세부 카테고리 선택 (큰 틀당 5~10개)
3. 모임 형태 선택 (`offline` / `online`) — `hobby_game_online` 등 온라인 전용 세부는 기본 `online`
4. 공통 정보 입력 (제목, 시간, 인원)
5. 형태별 정보 입력 (`offline`: 집결 장소/좌표, `online`: 플랫폼/접속 정보)
6. (선택) 친구 초대, AI 제목·설명 초안
7. 생성 → 지도에 마커 표시 (기본 **전체 공개**, 온라인은 온라인 전용 마커)

### 3.5 S5. 친구 추가·위치 공유

**경로 A — 앱 밖 실제 친구**

1. 친구 탭 → 닉네임 검색 / 친구 코드 / QR
2. 친구 요청 → 수락 → 위치 공유 모드 설정 (정확 / 대략 / 안 함)

**경로 B — 모임에서 만남**

1. 공개 모임 참여 → 참여자 프로필에서 **친구 추가** (선택)
2. 모임 종료 후 "오늘 함께한 사람" 목록에서 친구 요청

**경로 C — 연락처 초대**

1. 친구 탭 → 연락처 권한 허용
2. 가입자: 친구 요청 / 미가입자: SMS·초대 링크 발송

### 3.6 S6. 모임 합류·조율

1. 모임 참여 → 모임 스코프 위치 공유 ON (기본 제안)
2. 모임 상세·복숭아 허브에서 참여자 합류 현황 확인 (`출발` / `이동 중` / `근처` / `도착`)
3. 모임 전용 그룹 채팅으로 조율 ("5분 늦어요" 등)
4. 모임 종료 → 모임용 위치 자동 OFF

| 위치 권한 거부 | 지도 중심 불가 → 권한 안내·재요청 |
| 네트워크 오류 | `network` 코드 → 재시도 안내 |
| 모임 정원 초과 | 참여 불가 안내 |
| 신고·차단 | 프로필·모임에서 신고 → 차단 시 상호 비노출 |

### 4.4 위치·친구 기능 상세 (생명주기/권한 규칙 추가, 안전/신고/소개팅 정책 추가)

#### 위치 공유 모드 (젠리식)

| 모드 | 상대에게 보이는 것 | 용도 |
| --- | --- | --- |
| `precise` | 실시간에 가까운 좌표·이동 | 합류 중, 택시 탑승 직전 |
| `approximate` | 동네/캠퍼스 단위 | 평소 친구에게 대략 공유 |
| `off` | 마커 없음 | 프라이버시 |

- 친구마다 모드를 다르게 설정 가능
- 기본값: `approximate` 권장

#### 모임 스코프 위치 공유

- 해당 `meetingId` 참여 중 + `recruiting`/`ongoing` 상태일 때만
- **같은 모임 참여자에게만** 노출 (친구 관계와 별개)
- 모임 종료 시 자동 OFF
- 참여 시 동의: "이 모임의 다른 참여자에게 합류용 위치가 공유됩니다."

#### 합류 현황 (`arrivalStatus`) (AI/온보딩 구체화)

| 값 | 설명 |
| --- | --- |
| `not_started` | 아직 출발 안 함 |
| `on_the_way` | 이동 중 |
| `nearby` | 집결지 근처 |
| `arrived` | 도착 |

- **방식: 알고리즘(ALG)** — AI가 아님. GPS↔집결지 거리/ETA 계산 + 임계값 규칙
- 자동: 집결지까지 거리 기반 상태 전이 (ALG-01/ALG-02)
- 수동: "출발했어요" / "도착" 버튼 (위치 거부 시 대안)
- `hobby_game_*`(온라인 게임): 물리 거리 대신 `ready` / `in_call` / `playing` 상태 머신(ALG-03)

#### 건너뛰기 후 재진입 경로 (온보딩 건너뛰기 대응 추가)

건너뛴 사용자는 기본값으로 추천을 받지만, 다음 3가지 경로로 언제든 설정할 수 있다.

| 경로 | 진입 방법 | 조건 |
| --- | --- | --- |
| **① 설정 메뉴** | `S-SETTINGS > 추천 설정` → 4문항 재응답 또는 개별 항목 수정 | 항상 가능 |
| **② 추천 개선 CTA** | 메인 추천 영역에 "추천을 개선하고 싶으신가요? → 선호 설정하기" 버튼 | `isOnboardingCompleted=false` 인 경우 노출 |
| **③ 가입 후 3일 배너** | 메인 진입 시 인앱 배너 1회 노출 "맞춤 추천을 설정해보세요 →" | `isOnboardingCompleted=false` + 가입 후 3일 경과 + 배너 미노출 이력 없을 때 1회만 |

**규칙:**
- 배너(③)는 **1회만** 노출. 닫으면 다시 노출하지 않는다 (귀찮음 방지)
- 설정(①)에서 완료하거나 배너·CTA(②③)를 통해 4문항 모두 완료하면 `isOnboardingCompleted=true` 로 전환
- 개별 항목만 수정해도 즉시 추천에 반영 (전체 완료 불필요)

- `hobby_social_*` 프리뷰/상세에는 `안전 안내` 배지를 기본 노출

- 소셜 세부 모임은 거리 대신 `안전 우선 문구`를 보조 텍스트로 우선 노출 가능

#### 사용자 친화 원칙 (마커/상세 UX 추가)

1. 지도는 가리지 않고, 정보는 **단계적으로** 노출한다. (마커 → 프리뷰 → 상세)
2. 사용자가 가장 많이 누를 액션은 `참여하기`/`상세 보기` 2개로 제한한다.
3. 온라인/오프라인을 첫 시선에서 구분할 수 있어야 한다.
4. 제목이 짧아도 이해되도록 세부 카테고리/시간/인원을 함께 보여준다.
5. 신고/차단은 숨기지 말고 항상 접근 가능하게 둔다.

## 8. 비즈니스 규칙·정책 (생명주기/권한 규칙 추가, 안전/신고/소개팅 정책 추가, 채팅/알림/푸시 명세 추가)

| 항목 | 정책 |
| --- | --- |
| 로그인 | 이메일 + 비밀번호 |
| 이메일 | 아무 메일 허용 (학교 메일 제한 없음) |
| 비밀번호 | 영문+숫자 8~32자 (서버 재검증) |
| OTP | 6자리, 5분 유효, 재전송 30초 쿨다운 |
| 닉네임 | 2~10자, 유니크 |
| 생년월일 | 올해−100 ~ 올해, 유효한 날짜. 연령 확인·필터용 |
| 모임 기본 공개 | `public` 기본. friends/invite_only는 옵션 |
| 위치 공유 | 친구 모드 별도, 모임 스코프 별도. 모임 종료 시 자동 OFF |
| 친구 | 양방향 수락 필요. 모임 참여 ≠ 자동 친구 |
| 모임 채팅 | 모임 참여자만. 종료 후 N일 뒤 읽기 전용/삭제 |

### 8.4 소개팅(소셜) 정책 (안전/신고/소개팅 정책 추가, 19세 인증 구체화)

| 항목 | 정책 |
| --- | --- |
| 최소 연령 | 만 19세 이상 |
| 노출 원칙 | 소셜 세부(`hobby_social_*`)는 기본 공개 가능하되, 민감 정보 비노출 |
| 위치 정책 | 소셜 세부(`hobby_social_*`)는 참여 전 정밀 위치 비공개, 참여 후 선택 노출 |
| 대화 가드 | 첫 메시지 구간 안전 가이드 문구 고정 노출 |
| 위반 시 | 성희롱/사기/포교 신고는 소셜 카테고리 즉시 제한 후보 |

#### 8.4.1 연령 게이트 구현 명세 (19세 인증 구체화)

**MVP: 자기 신고(Self-Declaration) 방식**

가입 시 수집한 `birthDate`를 서버에서 계산하여 `hobby_social_*` 접근을 제어한다. 별도 본인인증 API 연동 없이 구현 가능하다.

**서버 연령 계산 규칙**

```
isAdult = (today - birthDate) >= 19년
```

- 기준: 한국 나이가 아닌 **만 나이** (생일 기준)
- 계산 시점: `hobby_social_*` 모임 **조회·생성·참여 요청 시마다** 서버에서 재계산
- 생일 당일: 당일 0시(KST)부터 성인으로 전환

**프론트엔드 동작**

| 상황 | 동작 |
| --- | --- |
| 미성년자가 메인 지도에서 `취미` 1단 선택 | `hobby_social_*` 세부 카테고리 목록 자체를 숨김 |
| 미성년자가 `hobby_social_*` 모임 마커에 접근 시 | 마커 비노출 (서버 필터링) |
| 미성년자가 API로 직접 `joinMeeting` 시도 시 | `social-age-restricted` 에러 반환 |
| 성인이 소셜 세부 카테고리 첫 진입 시 | "성인 대상 모임입니다. 안전하게 이용하세요" 안내 1회 노출 |

**클라이언트 우회 방지**

- FE에서 나이 계산하지 않음. **서버가 단일 진실 공급원(SSoT)**
- `getMeetingsNearby`, `getMeetingDetail`, `joinMeeting` 모두 서버에서 `isAdult` 재검증
- `birthDate` 수정 API는 **가입 후 변경 불가** (변경 필요 시 고객센터 경로만 허용)

**2차: 본인인증(PASS) 방식**

MVP 이후 소셜 카테고리 악용·분쟁 발생 시 통신사 본인인증(PASS·KMC 등) 도입을 검토한다.

| 항목 | 내용 |
| --- | --- |
| 연동 후보 | KMC(한국모바일인증), PASS(SKT/KT/LGU+), 나이스 본인인증 |
| 적용 범위 | `hobby_social_dating`, `hobby_social_group_dating` 한정 (소개팅·미팅) |
| 트리거 | 소셜 세부 모임 최초 참여 또는 생성 시 1회 |
| 비용 | 건당 약 50~100원 (서비스 규모에 따라 협상) |
| 데이터 보관 | 인증 결과(성인 여부 bool)만 저장. 주민번호·전화번호 저장 금지 |
| 재인증 | 기기 변경·탈퇴 후 재가입 시 재인증 |

**단계별 전환 조건**

| 단계 | 조건 | 방식 |
| --- | --- | --- |
| MVP | 출시 초기 | 자기 신고 (`birthDate`) |
| 전환 검토 | 소셜 신고 건수 월 N건 초과 또는 언론/법적 이슈 발생 | PASS 도입 검토 |
| 2차 적용 | 팀 결정 | PASS 연동, 기존 사용자 재인증 안내 |

### 8.5 매너 점수 정책 (평판 시스템 추가)

#### 기본 구조

- 기본값 **100점**, 범위 **0~120점**
- 계정 정지는 극단적 수단(0~19 구간)으로만. 일상 제재는 점수 기반 이용 저항으로 처리
- 점수 계산은 **서버 규칙 기반(ALG-07)**. AI-012(2차)에서 로그 학습으로 고도화 예정

#### 점수 변동 규칙

| 이벤트 | scoreDelta | 방식 | 이의 제기 |
| --- | --- | --- | --- |
| 노쇼 확정 | -15 | 자동 (24시간 후) | 24시간 내 가능 |
| 강퇴 확정 | -10 | 자동 (즉시) | 불가 |
| 신고 처리 — 경고 | -10 | 수동 (관리자) | 7일 내 1회 |
| 신고 처리 — 중대(성희롱·사기 등) | -30 | 수동 (관리자) | 7일 내 1회 |
| 모임 완주 (노쇼 없이 종료) | +1 | 자동 | 해당 없음 |
| 관리자 직접 조정 | 가변 | 수동 | 해당 없음 |

#### 구간별 이용 저항

| 구간 | 라벨 | 이용 제한 | 에러코드 |
| --- | --- | --- | --- |
| 80~120 | 정상 | 없음 | — |
| 60~79 | 주의 | 모임 생성 1일 1개 제한 | `manner-score-restricted` |
| 40~59 | 경고 | 소셜 카테고리 이용 정지, 모임 생성 불가 (참여만 가능) | `manner-score-restricted` |
| 20~39 | 위험 | 공개 모임 참여 불가, 친구 초대 모임만 허용 | `manner-score-restricted` |
| 0~19 | 정지 | 앱 이용 전면 제한 (읽기 전용) | `manner-score-restricted` |

#### 노출 정책 (UX)

**프로필 화면**

| 대상 | 노출 내용 |
| --- | --- |
| 본인 | 점수 숫자 + 라벨 표시 (`87점 · 정상`), 변동 이력 목록 제공 |
| 타인 | 라벨만 표시 (`✓ 매너 좋음` = 80+, 무표시 = 60~79, `⚠ 주의` = 40~59) |
| 경고 이하(~59) | 타인 프로필에 `⚠ 이 사용자는 이용 제한 중입니다` 배지 추가 |

**모임 프리뷰·상세 화면 — 주최자 배지**

| 주최자 구간 | 표시 |
| --- | --- |
| 80+ (정상·주의) | 표시 없음 (깔끔한 UX 유지) |
| ~59 (경고 이하) | `⚠ 신고 이력 있음` 경고 배지 |

#### 관리자 개입 최소화 원칙

- 노쇼·강퇴·모임 완료는 **ALG-07이 자동 처리** → 관리자 불필요
- 신고는 AI-005 자동 탐지로 1차 필터 → 임계 초과 시만 관리자 큐
- 관리자는 **이의 제기 처리·재심·영구 정지**만 담당

## 12. AI·알고리즘 기능 (안전/신고/소개팅 정책 추가, AI/온보딩 구체화)

**원칙**

1. 지도·모임·친구·합류 거리 등 핵심 기능은 **AI 없이도 동작**
2. AI는 보조. 실패 시 해당 UI만 숨김
3. **합류 거리·도착 상태·필터·노쇼 판정은 알고리즘(ALG)**. AI라고 표기하지 않음

### 12.0 구분 정의 (AI/온보딩 구체화)

| 구분 | 의미 | 예 |
| --- | --- | --- |
| ALG (알고리즘) | 공식·임계값·상태 머신 | 남은 km, 합류 상태, 필터 |
| AI | 점수 추정·말투 생성·위험 탐지 | 추천, 초안, 스팸 |
| Hybrid | 온보딩 가중치(규칙) + 추천 스코어 | 개인화 추천 |

### 12.1 알고리즘 맵 — AI 아님 (AI/온보딩 구체화)

| ID | 기능 | 화면 | 입력 | 출력 | 규칙 |
| --- | --- | --- | --- | --- | --- |
| ALG-01 | 남은 거리·ETA | 합류 현황 | GPS, 집결지 | `1.2km · 약 12분` | Haversine + 단순 ETA |
| ALG-02 | 합류 상태 | 합류 현황 | 거리, 버튼 | `not_started`→`arrived` | >500m 이동중, ≤500m 근처, ≤80m 도착 |
| ALG-03 | 온라인 합류 상태 | 온라인 게임 모임(`hobby_game_*`) | 사용자 탭 | `ready`/`in_call`/`playing` | 상태 머신 (거리 미사용) |
| ALG-04 | 카테고리 필터 | 메인 칩 | category/sub/mode | 마커 목록 | 서버 쿼리 |
| ALG-05 | 마커 클러스터 | 메인 지도 | 좌표 근접 | 묶음 마커 | 줌·거리 임계 |
| ALG-06 | 노쇼 후보 | 종료 후 | startAt+15분, arrived | `no_show_candidate` | 규칙 판정 |
| ALG-07 | 매너 점수 자동 차감 | 서버 배치 | `UserPenaltyEvent.status=pending` + 24시간 경과 / 강퇴 확정 / 모임 완료 | `mannerScore` 갱신 | 규칙 기반 자동 적용 |
| ALG-08 | 제목 템플릿 조합 | 모임 만들기 | category + subcategory + 시간 | 템플릿 후보 3개 버튼 | 카테고리별 미리 정의된 문자열 테이블 |
| ALG-09 | 채팅 키워드 필터 | 채팅 (`sendMessage`) | 메시지 본문 | 발송 허용 / 차단 + 경고 반환 | 서버 DB 금지 키워드 테이블 매칭. 운영진이 점진적으로 추가 |

### 12.2 MVP AI 세분화 맵 (AI/온보딩 구체화)

MVP AI를 단일 “추천/초안”이 아니라 **기능 단위로 쪼갠다.**

#### A. 개인화·추천 계열 (추천 구조 가독성 개선)

> **한 줄 요약**: 사용자가 메인 지도를 열었을 때, 수많은 모임 중 "이 사람에게 맞을 것 같은" 모임을 앞에 내세워 주는 기능.

**사용자가 실제로 보는 것**

| 형태 | 위치 | 보이는 것 |
| --- | --- | --- |
| 지도 하이라이트 | 메인 지도 마커 | 상위 N개 마커에 별 아이콘 + `추천` 뱃지. 나머지 마커와 시각적 차별화 |
| 추천 사유 라벨 | 마커 프리뷰 / 추천 카드 | 뱃지 옆 라벨 1개: `가까움` / `선호 카테고리` / `저녁 시간대` 중 기여도 가장 높은 것 |
| 추천 리스트 | 복숭아 FAB 탭 | 상위 5개 카드 리스트. 구성: 카테고리 아이콘, 제목, 거리/시간, 사유 라벨 |

**어떻게 점수를 내나 (AI-001-S)**

온보딩에서 설정한 중요도 순위(`rankWeights`)를 가중치로 삼아 각 모임에 `finalScore`를 계산한다.

```text
finalScore =
  w_distance * proximityScore    // 거리 (가까울수록 높음)
+ w_clarity  * clarityScore      // 모임 설명 충실도 (제목+설명 충실할수록 높음)
+ w_cost     * costFitScore      // 비용 적합도 (무료=1.0, 유료=0.5)
+ w_time     * timeFitScore      // 시작 시각과 선호 시간대 일치도
+ w_taste    * categoryMatch     // 선호 카테고리 일치 여부 (일치=1.0)
+ w_rep      * reputationScore   // 주최자 매너 점수 (mannerScore/100, §8.5)
+ contextBoost                   // 현재 시간대·시험기간 부스팅 (AI-001-T)
```

`w_*`는 온보딩 `rankWeights`(또는 건너뛰기 시 기본값)에서 온다.

**기피 타입 하드 필터 (AI-001-X)**

`avoidedMeetingTypes`에 해당하는 모임은 점수 계산 전에 추천 목록에서 제외한다. 지도 탐색에서는 여전히 볼 수 있음 (추천만 제외).

**추천 없을 때 Fallback 흐름**

```
온보딩 완료     → AI-001-S 스코어 계산 → 상위 N개 추천
온보딩 건너뛰기 → 기본 가중치로 AI-001-S → 상위 N개 추천
추천 N개 미만   → 거리순 fallback으로 채움
AI 서버 실패   → 하이라이트·리스트 UI 숨김, 마커는 정상 표시
```

**세부 ID 맵**

| ID | 역할 | 화면 | 담당 |
| --- | --- | --- | --- |
| AI-001-P | 온보딩 순위 → `rankWeights` 변환 저장 | S-ONBOARD-3 | FE+BE |
| AI-001-S | `finalScore` 계산 (위 점수식) | 서버 | AI+BE |
| AI-001-H | 상위 N개 마커에 추천 뱃지 표시 | 메인 지도 | FE |
| AI-001-L | 상위 N개 추천 카드 리스트 표시 | 복숭아 허브 | FE |
| AI-001-W | 점수 기여 요인 1개를 사유 라벨로 표시 | 카드/프리뷰 | AI+FE |
| AI-001-T | 현재 시각·시험기간 기반 `contextBoost` 계산 | 스코어 | AI |
| AI-001-C | `preferredCategories` 기반 `categoryMatch` 계산 | 스코어 | AI |
| AI-001-X | `avoidedMeetingTypes` 하드 필터 적용 | 추천 직전 | BE+AI |

#### B. 생성 보조 계열 (생성 보조 구조 재정의)

생성 보조는 **3단계 구조**로 동작한다. 1단계(ALG)는 AI 없이도 항상 동작하며, AI 실패 시 1단계로 자동 fallback.

**3단계 구조**

| 단계 | 역할 | 담당 | AI 필요 |
| --- | --- | --- | --- |
| 1단계 | 카테고리별 미리 정의된 **제목 템플릿 3개 버튼** 노출 → 사용자 선택 또는 직접 입력 | ALG-08 | No |
| 2단계 | 선택한 템플릿 + 장소·시간·인원 입력값을 조합해 **AI가 말투 입혀 1줄 완성** | AI-002-T + AI-002-S | Yes (실패 시 1단계 fallback) |
| 3단계 | 제목 확정 후 설명 초안 생성 버튼 탭 → **AI가 1~2문장 생성**, 사용자 수정 가능 | AI-002-D | Yes (실패 시 빈칸 유지) |

| ID | 기능 | 화면 | 입력 | 출력 | 담당 |
| --- | --- | --- | --- | --- | --- |
| AI-002-T | 제목 말투 완성 | 모임 만들기 | ALG-08 템플릿 + 장소/시간/인원 | 말투 입힌 제목 1줄 | ALG+AI |
| AI-002-D | 설명 초안 | 모임 만들기 | 제목 + 키워드 | 설명 1~2문장 | AI |
| AI-002-S | 종류별 말투 규칙 | 초안 생성 시 | category/subcategory | 말투 파라미터 전달 | ALG (규칙 테이블) |
| AI-002-U | 세부 카테고리 제안 | 큰 틀 선택 후 | 제목·키워드(선택) | subcategory 후보 1~3 | ALG+AI |
| AI-002-N | 유사 모임 안내 | 생성 직전 | 같은 시간·장소 근처 모임 | 비슷한 모임 N개 링크 | BE |

**말투 규칙 테이블 (ALG-08 + AI-002-S 공통 입력, 설문 Ground Truth 반영):**

| category | 말투 패턴 | 템플릿 예시 |
| --- | --- | --- |
| taxi | 시간+출발+도착+구함 | [시간] [출발]→[도착] 택시 같이 타실 분? |
| study | 카공/빡공 짧은 구함체 | [장소] 카공 같이 하실 분~ / 오늘 빡공 ㄱㄱ |
| sports | 초단문 | [종목] ㄱㄱ / [종목] n인 구합니다 |
| meal | 학식/교시/사람? | [시간] [음식종류] 같이 먹을 사람? |
| hobby_social_* | 과한 친근·유도 문체 지양 + 안전 안내 포함 | [목적] 편하게 이야기 나눠요 |
| hobby_game_* | 랭크/보이스/인원 | [게임명] [티어] [n]인 구합니다 |

### 12.6 온보딩 ↔ 추천 연결 (AI/온보딩 구체화)

```text
온보딩 순위(1~4) + 기피 타입
  → rankWeights / avoidedMeetingTypes 저장
  → AI-001-X로 기피 하드 필터
  → AI-001-S 개인 w로 스코어
  → AI-001-H/L 메인·복숭아에 반영
  → (이후) 클릭/참여 로그로 w 미세 조정
```

“우선도 조합으로 AI 학습”의 MVP 의미 = **순위→가중치 초기화 + 기피 하드 필터 + 이후 행동 로그로 보정**.  
거대 모델 재학습이 필수는 아님.

### 확정된 제품 방향

- **정의:** 누구나 쉽게 모든 모임을 만들고 참여
- **발견:** 모임 기본 전체 공개. 친구 전용·초대만은 옵션
- **지도:** 4종 동시 표시, 상단 칩으로 종류 하나만 필터
- **위치:** 젠리식 모드. 모임 참여 중 합류용 위치 공유, 종료 시 OFF
- **친구:** (1) 원래 아는 사람—코드/연락처 (2) 모임에서 만남—선택 추가
- **모임:** 채팅 + 합류 현황. 참여자 ≠ 자동 친구
- **인증:** 이메일+비밀번호, 아무 메일, 생년월일 수집
- **AI:** 근처 추천 + 생성 초안
- **지도 SDK:** MVP Google Maps, 교체 가능
- **메인 UI:** + 모임 만들기 / 복숭아 허브 / 메뉴
- **대상:** 1차 대학생, 가입 제한 없음, 이후 레이어 확장
