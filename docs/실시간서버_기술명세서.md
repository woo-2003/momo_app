폴링 대신 **같은 `momo_server`에 WebSocket을 붙여** 모임 채팅만 실시간으로 한다. GPS·위치 푸시는 하지 않는다.

---

## 1. 한 줄

로그인 JWT로 소켓에 붙고, **그 모임의 참여자만** 같은 방에 들어가 메시지를 주고받는다. 저장은 기존 Firestore `messages`와 동일하다.

---

## 2. 구조

```
앱  ──HTTP──►  Express (가입/로그인/모임 CRUD)     [기존·유지]
앱  ──WS────►  같은 프로세스 Socket.IO
                 인증: JWT
                 방: meeting:{meetingId}
                 저장: Firestore (HTTP POST와 같은 로직)
```

새 서버를 쪼개지 않는다. `PORT` 하나(기본 3000)에서 HTTP + WS.

라이브러리: `socket.io` (Flutter는 `socket_io_client`).

---

## 3. 연결

1. HTTP로 로그인 → `token` (기존).
2. 소켓 연결 시 쿼리 또는 handshake: `token=<JWT>`.
3. 서버가 JWT 검증. 실패면 연결 거부.
4. `sub` = `userId`.

```
ws://localhost:3000   (안드 에뮬: 10.0.2.2:3000)
```

---

## 4. 이벤트

| 방향 | 이름 | 내용 |
| --- | --- | --- |
| C→S | `join` | `{ meetingId }` — 멤버가 아니면 에러 |
| C→S | `leave` | `{ meetingId }` |
| C→S | `chat` | `{ meetingId, body }` — 1~500자 |
| S→C | `chat` | `{ messageId, meetingId, senderId, nickname, body, createdAt }` |
| S→C | `error` | `{ code, message }` |

`join` 성공 후에만 그 방의 `chat`을 받는다.

과거 메시지는 소켓으로 안 보낸다. **첫 화면은 기존 `GET /meetings/:id/messages`**, 이후만 소켓.

---

## 5. 규칙

- `chat` 수신 시: 멤버인지 확인 → Firestore에 저장 → 방 전체에 `chat` broadcast.
- 모임 `cancelled`면 `chat` 거부 (`meeting-cancelled`).
- 주최자 취소는 HTTP `POST .../cancel` 유지. 소켓으로 파기하지 않음.
- 모임 생성·목록·지도는 **HTTP만**. 실시간으로 마커를 안 밀어줌.

---

## 6. 안 하는 것

- 위치 실시간 공유
- 읽음·타이핑 중
- FCM 푸시
- 1:1 DM
- 다중 서버 스케일아웃 (메모리 방만, 인스턴스 1개)

---

## 7. 구현 순서

1. Express에 Socket.IO 붙이기 + JWT handshake  
2. `join` / 멤버 체크  
3. `chat` 저장 + broadcast  
4. 앱: 채팅방 입장 시 소켓, 히스토리는 GET  

HTTP `POST /meetings/:id/messages`는 남겨도 된다. 실시간 경로와 **같은 저장 함수**를 쓰면 된다.
