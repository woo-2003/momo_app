# momo 모임·채팅 프로토타입 기술명세서

| 항목 | 내용 |
| --- | --- |
| 문서명 | 모임 생성/파기 · 지도 마커 · 채팅 프로토타입 기술명세서 |
| 상태 | **미구현 — 구현 계약(목표)** |
| 작성일 | 2026-08-20 |
| 전제 | 인증·세션·Firestore `users`는 [`인증_기능명세서.md`](인증_기능명세서.md)대로 **완료** |
| 관련 | [`기획서.md`](기획서.md)를 **축소**한 1차 서버 범위 |
| 대상 코드 | `momo_server/` (신규 라우트·컬렉션). Flutter 화면은 본 문서 후속 |

본 문서는 제품 전체 MVP가 아니라, **백엔드가 아직 없는 모임/채팅을 프로토타입으로 붙이기 위한 서버 계약**이다. 기획서와 충돌하면 **이 문서가 프로토타입 SSoT**이고, 기획서는 이후 확장 목표로 둔다.

---

## 1. 목적

- 택시 · 온라인 게임 · 운동 모임을 **만들고, 취소(파기)하고, 지도에 올리고, 참여자끼리 채팅**한다.
- **사용자 GPS·실시간 위치·합류 현황은 제외**한다. (다른 개발자 담당)
- 지도는 **모임에 저장된 집결 좌표**만 사용한다. 내 위치 파란 점은 본 범위 밖이다.

---

## 2. 범위

### 2.1 In scope (프로토타입)

| ID | 기능 | 비고 |
| --- | --- | --- |
| M-01 | JWT로 보호된 모임 API | `Authorization: Bearer <accessToken>` |
| M-02 | 모임 생성 | 카테고리 3종, 주최자 자동 참여 |
| M-03 | 모임 파기(취소) | 주최자만. 문서 삭제 대신 `cancelled` |
| M-04 | 모임 목록 (지도 마커용) | `open`만. bbox·내 위치 필터 **없음** |
| M-05 | 모임 상세 | 채팅 진입용 |
| M-06 | 참여 / 나가기 | 정원, 취소된 모임 참여 불가 |
| M-07 | 모임 채팅 | 텍스트, **폴링**. WebSocket·푸시 없음 |

### 2.2 Out of scope (명시적 제외)

| 항목 | 이유 |
| --- | --- |
| 기기 GPS, 백그라운드 위치, 친구 위치, 모임 스코프 위치 | 타 개발자 |
| 합류 현황 (`arrivalStatus`) | 위치 의존 |
| `getMeetingsNearby`의 bbox / 거리 정렬 | GPS 없이도 전체 `open` 목록으로 마커 가능 |
| 밥약·스터디, 2단 `subcategory` 전체 | 3종만 |
| `visibility` friends / invite_only | 전부 `public` |
| 자동 생명주기 (`recruiting`→`ongoing` 시각 전이) | `open` / `cancelled`만 |
| 노쇼·매너점수·신고·강퇴·알림 | 이후 |
| 친구 1:1 DM | 이후 |
| Firebase Auth | 기존과 같이 bcrypt+JWT |
| 앱의 Firestore 직접 접근 | Express Admin만 |

## 3. 아키텍처

```
Flutter (이후)
  AuthSession.accessToken
       │  Authorization: Bearer
       ▼
momo_server
  authMiddleware(JWT)
       ├─ meetings 라우트
       └─ messages 라우트
            ▼
     Firebase Admin
       Firestore
         users              (기존)
         meetings           (신규)
         meeting_members    (신규)
         meeting_messages   (신규)
```

기존 OTP·로그인 라우트는 변경하지 않는다. 모임 API만 추가한다.

저장소 스위치(`STORAGE=sqlite`)는 **프로토타입에서 Firestore만** 사용한다. SQLite 모임 테이블은 만들지 않는다.

## 4. 도메인 모델 (축소)

### 4.1 카테고리 (`category`)

기획서 1단+2단을 쓰지 않고 **1단 3개만** 쓴다.

| 값 | 이름 | `meetingMode` 기본 | 지도 |
| --- | --- | --- | --- |
| `taxi` | 택시 합승 | `offline` | 집결 `lat`/`lng` 필수 |
| `sports` | 운동 | `offline` | 집결 `lat`/`lng` 필수 |
| `game` | 온라인 게임 | `online` | 좌표 **선택**. 없으면 목록/상세만, 지도 마커 생략 |

기획서의 `hobby_game_*`는 프로토타입에서 `category=game` + `categoryFields.gameName`으로 흡수한다.

마커 색 (프론트 참고): 택시 노랑, 운동 빨강, 게임 보라(또는 ONLINE 배지).

### 4.2 상태 (`status`)

| 값 | 의미 | 지도 | 참여 | 채팅 전송 |
| --- | --- | --- | --- | --- |
| `open` | 모집·진행 중 (구분 안 함) | 표시 | 가능 (정원 내) | 참여자만 |
| `cancelled` | 주최자 파기 | 비표시 | 불가 | 불가 (과거 메시지 읽기는 허용 가능) |

`ended` / `ongoing` / `recruiting`은 프로토타입에 두지 않는다.

### 4.3 역할

| 역할 | 권한 |
| --- | --- |
| 주최자 (`creatorId`) | 생성 시 자동 멤버, 취소, 채팅 |
| 참여자 | 나가기, 채팅 |
| 비참여자 | 공개 목록·상세 조회, 참여 요청. 채팅 조회/전송 불가 |

## 5. Firestore 스키마

문서 ID는 Auto-ID. 시각은 **ISO-8601 UTC 문자열** (`createdAt`과 인증 users와 동일 관례).

### 5.1 `meetings/{meetingId}`

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| title | string | Y | 1~40자 |
| description | string | N | 최대 500자 |
| category | string | Y | `taxi` \| `sports` \| `game` |
| meetingMode | string | Y | `offline` \| `online` |
| status | string | Y | `open` \| `cancelled` |
| visibility | string | Y | 항상 `public` |
| placeName | string | offline Y / online N | 집결·만남 장소 이름 |
| latitude | number | offline Y | 생성 폼에서 입력. **기기 GPS 아님** |
| longitude | number | offline Y | 동일 |
| startAt | string | Y | ISO-8601 |
| maxMembers | number | Y | 2~50 |
| currentMembers | number | Y | 시스템. 생성 시 1 |
| creatorId | string | Y | JWT `sub` (서버 `users` 문서 ID) |
| categoryFields | map | N | 아래 4.4 |
| cancelledAt | string | 취소 시 | |
| createdAt | string | Y | |

`game` + `online`이면 `placeName`/`lat`/`lng` 생략 가능.

### 5.2 `meeting_members/{id}` 또는 `meetings/{id}/members/{userId}`

프로토타입 권장: **서브컬렉션** `meetings/{meetingId}/members/{userId}`

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| userId | string | 문서 ID와 동일 |
| nickname | string | 가입 시점 닉네임 스냅샷 (채팅 표시용) |
| role | string | `host` \| `member` |
| joinedAt | string | |

정원은 `currentMembers`와 members 문서 수를 맞춘다. 참여/나가기는 **트랜잭션**으로 `currentMembers`와 멤버 문서를 같이 갱신한다.

### 5.3 `meetings/{meetingId}/messages/{messageId}`

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| senderId | string | |
| nickname | string | 발송 시점 스냅샷 |
| body | string | 1~500자, text만 |
| createdAt | string | 서버 시각 |

삭제 플래그·신고 필드는 두지 않는다.

### 5.4 `categoryFields`

**taxi**

| 키 | 필수 | 설명 |
| --- | --- | --- |
| destinationName | Y | 도착지 이름 (좌표 없음 — GPS 제외) |
| departPlaceName | N | 탑승 지점. 없으면 `placeName` |
| costShareNote | N | 더치 메모 |

**sports**

| 키 | 필수 | 설명 |
| --- | --- | --- |
| sportType | Y | 예: `futsal`, `running`, `gym`, `other` |

**game**

| 키 | 필수 | 설명 |
| --- | --- | --- |
| gameName | Y | 예: `lol`, `valorant`, `mobile`, `other` |
| platformNote | N | 보이스·티어 메모 |

## 6. 인증

모든 모임·채팅 엔드포인트:

```
Authorization: Bearer <JWT>
```

- 없거나 서명/만료 실패 → **401** `{ success: false, message: "unauthorized" }`
- `sub`를 `creatorId` / `userId`로 사용한다. (앱 `AuthSession.userId`가 이메일이므로, **모임 API의 사용자 키는 JWT `sub`** 이다. 프론트는 토큰만 보내고 ID를 추측하지 말 것.)

기존 `/login` 응답 `user.id` = Firestore users 문서 ID = JWT `sub`.

## 7. HTTP API

Base URL은 인증과 동일 (`localhost:3000` / 안드 에뮬 `10.0.2.2:3000`).  
공통 JSON: `{ success, message?, ... }`

### 7.1 `POST /meetings` — 생성

**요청**

```json
{
  "title": "심야 안양역 합승",
  "description": "2명 구함",
  "category": "taxi",
  "meetingMode": "offline",
  "placeName": "성결대 정문",
  "latitude": 37.3801,
  "longitude": 126.9281,
  "startAt": "2026-08-20T15:00:00.000Z",
  "maxMembers": 4,
  "categoryFields": {
    "destinationName": "안양역",
    "departPlaceName": "정문 택시승강장"
  }
}
```

게임 예시:

```json
{
  "title": "롤 내전 5인",
  "category": "game",
  "meetingMode": "online",
  "startAt": "2026-08-20T18:00:00.000Z",
  "maxMembers": 5,
  "categoryFields": { "gameName": "lol" }
}
```

**검증**

- `category` ∈ { taxi, sports, game }
- `taxi`/`sports`는 `meetingMode=offline` 강제 가능 (프로토타입)
- `game`은 `online` 기본. offline이면 lat/lng 필수
- offline은 `placeName`, `latitude`, `longitude` 필수
- `maxMembers` 2~50, `startAt` 파싱 가능
- 카테고리별 `categoryFields` 필수 키

**성공 201**

```json
{
  "success": true,
  "meetingId": "abc",
  "status": "open",
  "createdAt": "2026-08-19T15:30:00.000Z"
}
```

부수 효과: `members/{sub}` 문서 `role=host`, `currentMembers=1`.

### 7.2 `GET /meetings` — 지도·리스트

쿼리 (모두 선택):

| 파라미터 | 설명 |
| --- | --- |
| category | `taxi` \| `sports` \| `game` |
| meetingMode | `offline` \| `online` |

기본 필터: `status=open`만. `cancelled` 제외.

bbox·limit 커서는 프로토타입에서 생략. 결과 상한 **100건** (오래된 `createdAt` 제외, `startAt` 오름차순).

**성공 200**

```json
{
  "success": true,
  "items": [
    {
      "meetingId": "abc",
      "category": "taxi",
      "meetingMode": "offline",
      "status": "open",
      "title": "심야 안양역 합승",
      "startAt": "2026-08-20T15:00:00.000Z",
      "currentMembers": 2,
      "maxMembers": 4,
      "placeName": "성결대 정문",
      "latitude": 37.3801,
      "longitude": 126.9281
    }
  ]
}
```

`game`+`online`이고 좌표가 없으면 `latitude`/`longitude`/`placeName`은 `null`. 프론트는 마커를 그리지 않고 리스트에만 넣는다.

### 7.3 `GET /meetings/:id` — 상세

비로그인도  eventual 공개가 기획 기본이나, 프로토타입은 **로그인 필수**로 단순화한다.

**200** — 위 목록 필드 + `description`, `categoryFields`, `creatorId`, `isHost`, `isMember`, `members` (userId, nickname, role).

**404** — 없음.

### 7.4 `POST /meetings/:id/cancel` — 파기

주최자만. `open` → `cancelled`, `cancelledAt` 기록.

이미 `cancelled`면 409. 주최자 아니면 403.

목록·지도에서 즉시 제외. 메시지는 남기되 `POST messages`는 403 `meeting-cancelled`.

### 7.5 `POST /meetings/:id/join`

- `open`이 아니면 409 `meeting-ended` (취소 포함, 코드명은 기획서 유지)
- `currentMembers >= maxMembers` → 409 `meeting-full`
- 이미 멤버 → 200 멱등 `{ success: true, alreadyMember: true }`
- 성공 시 멤버 문서 추가, `currentMembers++`

### 7.6 `POST /meetings/:id/leave`

- 비멤버 → 403
- 주최자 → 403 `host-cannot-leave` (프로토타입은 **취소 API로만 파기**)
- 그 외 멤버 삭제, `currentMembers--`

### 7.7 `GET /meetings/:id/messages`

쿼리: `limit` 기본 50 최대 100, `before` (ISO, 선택) 로 이전 페이지.

- 멤버만. 아니면 403 `not-participant`
- `cancelled`여도 **읽기 허용**

**200**

```json
{
  "success": true,
  "items": [
    {
      "messageId": "m1",
      "senderId": "u1",
      "nickname": "qwerty",
      "body": "3분 뒤에 나가요",
      "createdAt": "2026-08-20T14:01:00.000Z"
    }
  ]
}
```

`items`는 `createdAt` 오름차순.

### 7.8 `POST /meetings/:id/messages`

```json
{ "body": "3분 뒤에 나가요" }
```

- 멤버만, `open`만 전송
- `body` trim 후 1~500자
- 성공 201 `{ success: true, messageId, createdAt }`

실시간: 클라이언트 **2~3초 폴링** `GET .../messages`. 서버 푸시 없음.

## 8. 에러 코드

HTTP JSON `message`와 앱 `AuthException`/`MeetingException` 매핑용.

| code | HTTP | 상황 |
| --- | --- | --- |
| `unauthorized` | 401 | JWT 없음/무효 |
| `forbidden` | 403 | 주최자 아닌 취소, 비멤버 채팅 |
| `not-participant` | 403 | 채팅 조회 |
| `host-cannot-leave` | 403 | 주최자 leave |
| `meeting-cancelled` | 403 | 취소 후 전송 |
| `validation` | 400 | 필드 누락·형식 |
| `meeting-full` | 409 | 정원 |
| `meeting-ended` | 409 | 취소된 모임 참여 |
| `not-found` | 404 | 모임 없음 |
| `network` / `server` | 0 / 500 | 기존과 동일 |

## 9. 지도 연동 계약 (GPS 제외)

| 계층 | 책임 |
| --- | --- |
| 서버 | `GET /meetings`의 `latitude`/`longitude`/`category` |
| 프론트 지도 | 해당 좌표에 종류별 마커. 탭 → 상세 |
| GPS 모듈 (타 담당) | 내 위치 카메라 이동, 권한. **본 API를 바꾸지 말 것** |

생성 화면의 좌표 입력(프로토타입):

- 임시: 위경도 숫자 입력 또는 고정 캠퍼스 좌표 프리셋
- Places/GPS 피커는 GPS 담당 또는 2차

온라인 게임은 지도에 안 올려도 프로토타입 완료로 본다.

## 10. 프론트 연동 시 참고 (서버 계약만)

구현 순서 권장:

1. 서버: JWT 미들웨어 → POST/GET meetings → cancel
2. 앱: 만들기 폼 + 지도/리스트에 마커 (토큰은 `SessionStore`)
3. 서버: join/leave
4. 서버+앱: 채팅 폴링

도메인: `AuthRepository`와 분리해 `MeetingRepository`를 둔다. HTTP는 `EmailOtpService`와 같은 base URL.

**JWT `sub` vs `AuthSession.userId`:** 세션의 userId는 이메일이다. `isHost`는 상세 API 플래그를 쓰거나, 로그인 응답의 `user.id`를 세션에 추가로 저장하는 쪽이 안전하다. (인증 명세서 14.3 차이점)

## 11. 구현 순서 (백엔드)

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| B0 | `authMiddleware.js` — Bearer 검증 | 보호 라우트 401 |
| B1 | `meetings` 생성·목록·상세 | 콘솔/curl로 CRUD |
| B2 | cancel | 목록에서 사라짐 |
| B3 | members join/leave + 트랜잭션 | 정원 409 |
| B4 | messages GET/POST | 비멤버 403, 폴링으로 메시지 증가 |
| B5 | (선택) `npm run` 스모크 스크립트 | 해시 없는 로그 |

파일 배치 제안:

- `momo_server/middleware/auth.js`
- `momo_server/routes/meetingRoutes.js`
- `momo_server/services/meetingService.js`

`server.js`에 `app.use("/", meetingRoutes)` 추가.

## 12. 검수 체크리스트 (프로토타입)

## 13. 기획서 대비 축소 요약
