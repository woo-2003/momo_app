## 1. 제품 개요

### 1.1 한 줄 정의

> **지금 내 근처에서, 오늘 안에 시작하는 번개를 지도에서 고르고, 약속 장소로 모여드는 동안만 쓰는 앱**

### 1.2 문제

사람을 구하는 글, 길을 보는 지도, “어디쯤이에요?” 채팅이 앱마다 갈라져 있다.  
사용자는 **오늘·여기·곧**만 보고 싶은데, 게시판은 어제 글과 며칠 뒤 약속을 섞어 둔다.

momo는 만능 모임 앱이 아니다. **번개가 열리고, 그 핀으로 모일 때까지만** 켠다.

### 1.3 제품 방향

| 축 | 내용 |
| --- | --- |
| 발견 | 지도에는 **오늘**, **근처**, **유효한** 번개만. 겹치면 **더 익은 모임이 위** |
| 집결 | 호스트 직접 지정 **또는** AI 추천. 최종은 호스트 |
| 합류 | 오는 길을 본다. **앱이 뒤에 있어도** 위치 전송. 끝나면 OFF |
| 복숭아 | 시간 익음(모임 점) + 거리 익음(사람). 매너 점수와 별개 |

- **서비스 지역:** 전국(지역 락 없음). 지도 기본 반경은 **근처 3km(초안, §12에서 확정)**.
- 학교 인증·캠퍼스 제한 없음. 밀도는 **짧은 시간 + 짧은 거리**.

하지 않는 것: 소개팅, 온라인 전용, 며칠 뒤 정기 동아리, 친구 상시 위치, 제목 AI Must, 출시 직후 광고 Must, 태그평가 Must.

### 1.4 핵심 가치

1. **발견** — 오늘 근처 번개를 지도에서 본다  
2. **집결** — 직접 또는 AI로 만날 곳을 정한다  
3. **합류** — 오는 중인지 보며 만난다  

### 1.5 MVP 범위

**포함:** 이메일 OTP + **PASS(통신사) 신원**, 지도, 번개 4종, 종류별 시계·익음, 장소 직접/AI, 택시 도착 즐겨찾기, 현재 인원 진행(2+), 합류 위치(백그라운드 포함), 채팅(텍스트+이미지)·신고 최소, 푸시(§8), 모임 추천.

**제외:** 소개팅·취미·온라인·비공개, 젠리식 친구 위치, 제목 AI Must, AdMob Must, 태그평가 Must.

### 1.6 팀

이승민 UI/UX · 정우영 기획/프론트 · 김동준 백엔드 · 김건희 AI

### 1.7 문서 깊이

제품 PRD + 상수·정책·장면 보강(핸드오프용 화면 ID·수락 기준 전문은 이번에 넣지 않음).

## 2. 타겟·가입

전국 사용자. 오늘 근처 번개가 필요한 사람. 학교 인증 없음.

| 항목 | MVP 방향 |
| --- | --- |
| 이메일 OTP | 유지(계정·로그인) |
| PASS·통신사 인증 | **도입 예정** — 이름·생년월일 등 **기본 신원을 통신사에서 수신** (앱에 생년월일 직접 입력 폼을 두는 방식이 아님) |
| 만 14세 미만 | **가입 방지 수단 검토** (수신한 생년월일 등으로 차단 가능 여부 포함) |
| 지도 “근처” | **3km 초안** (확정 §12) |

## 3. 사용자 시나리오

### 3.1 가입

랜딩 → 이메일 OTP → 비밀번호 → 닉네임 → **(예정) PASS·통신사 인증으로 신원 수신** → 메인  
직접 생년월일 입력 화면은 두지 않는다. PASS 연동 전 임시 플로우는 팀에 공유.

### 3.2 로그인

이메일·비밀번호 → JWT → 메인. 재실행 시 자동 로그인.

### 3.3 번개 찾아 참여

지도(근처) → 점(겹치면 더 익은 것 우선) → 카드 → 상세 → 참여·위치 동의 → 합류

### 3.4 번개 만들기

종류 → 시간·인원 → 장소(직접/AI) → (이동이면 도착·지금/예약) → 생성

### 3.5 진행·합류·종료

호스트 “현재 N명으로 진행”(N≥2) → 모집 잠금 → 합류(백그라운드 위치) → 종료 시 위치 삭제

| 거리 익음 | **500m+ / 200~500m / 50~200m / 도착(&lt;50m)** | 합류 사람 마커 |
| 합류 마커 | **사람** | 비주얼은 승민 |
| 위치 전송 주기 | **15초** | 아래 배민 참고 |

| 채팅 | **텍스트 + 이미지** | 실시간 방식은 BE 재량(소켓 권장) |

**시간 익음 기준 초안** (확정 §12)

| 단계 | 이동·지금 (모집 30~60초) | 60분 모집·당일형 |
| --- | --- | --- |
| 여유 | 남은 시간 &gt; 절반 | 남은 시간 &gt; 20분 (당일은 시작까지 &gt; 60분) |
| 임박 | 그 사이 | 5~20분 (당일 시작 60분~10분 전) |
| 마감직전 | 남은 &lt; 약 10초 또는 최후 구간 | &lt; 5분 (당일 시작 10분 전~) |

### 4.4 만날 장소 (직접 + AI)

확정 핀 하나. 최종 호스트. LLM이 좌표를 만들지 않음.

| 종류 | 직접 | AI |
| --- | --- | --- |
| 이동·지금 | 도착지(검색·지도·즐겨찾기) | **택시 부르기 좋은 탑승 지점** (대로·역·큰 건물. 골목·인도 제외) |
| 이동·예약 | 출발 시각·도착지·집결 직접 가능 | 같이 모이기 좋은 **탑승 가능 지점** |
| 밥·카페 | 이미 정한 곳 | 미정이면 **근처 식당·카페** |
| 카공 | 직접 | 카페·도서관 등 |
| 운동 | 직접 | 코트·운동장 등 |

스냅: 부적절 핀 → 대안 제안, 강행 시 “호스트 지정”.  
참여자 생긴 뒤 핀 이동은 호스트 수락 시에만.

### 4.5 현재 인원으로 진행

N≥2일 때 호스트가 진행 → 모집 잠금. 1명 불가.  
이동·지금: 타이머 종료 시 자동 출발 아님 → 호스트 확인(푸시 P8).

### 4.6 합류 위치

- **15초**마다 서버로 좌표 (합류 중인 참여자).
- **앱이 백그라운드여도 전송** (오는 중 확인이 목적). Android는 포그라운드 서비스·알림, iOS는 백그라운드 위치 권한·심사 문구 필요.
- POST에 목적지 좌표 없음. 서버가 모임 핀으로 거리·상태·거리 익음 계산.
- 상태: 출발 전 / 이동 중 / 근처 / 도착 / 응답 없음.
- 모임 종료·나가기·합류 종료 시 좌표 삭제.

**배민 참고:** 우아한형제들 규모를 가정한 공개 시스템 설계 글 기준, 라이더 앱은 **약 5초**마다 GPS를 올린다고 서술된 사례가 있다. 공식 공개 수치는 아님.  
momo는 라이더 상시 추적보다 부하·배터리가 작아도 되므로 MVP는 **15초**. 체감이 부족하면 10초로 내림(BE·앱 합의).

## 5. 화면·장면 UX

(장면 A~H는 4.2와 동일 골격. 아래는 4.3에서 바뀐 점만 강조.)

### 5.1 장면 A — 메인 지도

필터·`+`·복숭아·메뉴. 점 = 오늘·**근처(3km 초안)**·유효.  
시간 익음으로 점 모양이 익음. **겹치면 더 익은 모임이 위.**  
빈 지도: 만들기 CTA. 광고 없음.

### 5.2~5.5 만들기·장소·이동·밥

지도 반 + 시트. `직접` / `추천` / 스냅 경고.  
이동·지금: 도착지 → 탑승 추천 기본, 상단 모집 타이머 30~60초.

### 5.6 상세·참여

참여 시 위치 공유 동의(합류·**백그라운드 포함** 안내).

### 5.7 장면 G — 합류

집결 핀 + **사람** 마커(거리 익음). 목록에 상태·거리.  
백그라운드여도 상대에게 움직임이 보여야 함.  
상단 고정 알림(OS): “합류 위치를 공유 중”.  
종료 시 위치 OFF + “모임이 끝났어요”.

### 5.8 복숭아 버튼

참여 중 → 합류 바로가기. 없으면 오늘 추천 카드.

### 5.9 가입

OTP 유지. **PASS 화면 추가 예정.** 직접 생년월일 입력 UI는 제거·추가하지 않음.

## 6. 데이터·상태

### 6.1 주요 엔티티 (스케치)

**User:** userId, email, passwordHash, nickname, **(PASS) 이름·생년월일 등 신원 필드**, createdAt  

**Meeting:** category, startAt(오늘), place, placeSource, clock fields, capacity, taxiMode, **status**, creatorId …

**MeetingParticipant:** shareLocation, arrivalStatus, lastLat/Lng, lastLocationAt  

**UserFavoritePlace:** 도착지 ≤5  

**ChatMessage:** text and/or imageUrl, meetingId, senderId, createdAt  

### 6.2 모임 상태

```
recruiting → locked (진행/정원참/모집마감 후 호스트 확정)
         → live (합류·활동)
         → ended
         → cancelled
```

| 상태 | 참여 | 합류 위치 | 호스트 |
| --- | --- | --- | --- |
| recruiting | 가능 | 참여 후 가능 | 수정·취소·진행 |
| locked | 불가 | 가능 | 취소·종료 |
| live | 불가 | 가능 | 종료 |
| ended / cancelled | 불가 | OFF | — |

### 6.3 예외 (요약)

| 상황 | 동작 |
| --- | --- |
| 호스트 나가기/취소 | 참여자에게 P7. 위치 OFF. 채팅 읽기만 |
| 타이머 종료·인원 부족(이동·지금) | 자동 출발 없음. 호스트에 P8 |
| 정원 참 | 신규 참여 불가 |
| GPS 거부 | 참여는 가능하되 합류 맵에 “위치 없음”. 재요청 |
| 응답 없음(전송 끊김) | 상태 `응답 없음`, 마지막 좌표 유지·배너 |
| 이미지 전송 실패 | 토스트, 텍스트는 유지 가능 |

## 7. API·연동

### 7.1 인증

기존 OTP·signup·login + **PASS/통신사 연동(추가)**. signup에서 직접 birthdate 폼 의존 제거.

### 7.2 모임·장소·합류·채팅·푸시

모임 CRUD·참여·진행, recommendPlaces/snapPlace, 즐겨찾기,  
location POST(15초·백그라운드), members GET,  
채팅(텍스트·이미지 업로드), 신고,  
디바이스 토큰·푸시 발송.

### 7.3 장소 추천 I/O

입력: 종류, taxiMode, 도착지, 호스트·참여자 좌표, 시각, raw 핀  
출력: 후보 K — 이름, 좌표, 이유, 도보 분

### 7.4 채팅 실시간

**BE 재량.** 권장: WebSocket(또는 동등). 폴링도 MVP 가능. 새 메시지는 푸시 P3와 병행.

## 8. 정책·푸시

계정: 이메일 OTP + PASS 신원. 14세 미만 수단 검토.  
모임: 오늘·공개·오프라인·4종.  
채팅: 텍스트+이미지. 종료 후 읽기만, 30일 삭제.  
위치: 참여자·합류 구간만(백그라운드 포함), 종료 삭제.  
이동: 더치 동행. 유상운송 아님 문구 노출.  
수익: 점이 생긴 뒤. 빈 지도 광고 없음.

### 8.1 MVP 푸시 (전부 포함)

## 10. AI·알고리즘·장소 데이터 조사

### 10.1 원칙

지도·시계·거리는 AI 없이도 동작.  
AI 본업: (1) 지도에 앞에 둘 모임 (2) 장소 후보 줄 세우기.  
LLM이 위경도 생성 금지. 규칙 필터 없는 “모델만” 출시 금지.

### 10.2 장소 추천 요약

이동 → 픽업 가능 지점 / 밥·카페 → 식당·카페 / 카공 → 카페·도서관 / 운동 → 코트·운동장.

### 10.3 장소·POI API 조사 (건희·동준 선택용)

앱 지도 SDK와 **POI 검색 API는 분리**해서 골라도 된다. (예: 지도는 Google, POI는 카카오)

| 후보 | 강점 | 약점·주의 | momo 적합 |
| --- | --- | --- | --- |
| **카카오 로컬** | 국내 POI·한글, 키워드/카테고리, WGS84, **거리(m)** 응답, 카테고리 코드(음식점·카페 등) | 영업시간·평점은 약함. 쿼터·비즈 앱키 | **밥·카페·카공 1차 후보로 유력** |
| **네이버 지역/검색** | 국내 상호 인지도, 지도 생태계 | 좌표계(KATEC 등) 변환, 일부 검색 **결과 수 제한** 이슈 보고 | 보조·교차 검증용으로 가능 |
| **Google Places (New)** | 문서·영업시간·평점·글로벌, Flutter/Maps와 맞추기 쉬움 | 비용, 국내 골목·택시 픽업 적합도는 **직접 샘플링 필요** | 영업중 필터·상세에 유리. 지도 SDK와 통일 시 운영 단순 |
| **공공·자체 후보** | 택시 **정차·픽업** 지점은 상용 POI만으로 부족할 수 있음 | 구축 비용 | 이동 카테고리: 역·정류장·대로 교차 **규칙 후보 DB**를 초기에 두는 편을 권장 |

**팀 제안 (강제 아님)**

1. **식당·카페·카공:** 카카오 로컬(카테고리+반경) → 규칙(거리·종류) 줄 세우기. 필요 시 Google로 영업시간 보강.  
2. **운동:** 카카오/네이버 키워드·카테고리 + 호스트 직접 지정.  
3. **이동 탑승:** Places “식당”이 아님. **역·큰 건물·대로변 후보 테이블 + 스냅 규칙**을 1차로 두고, API는 보조.  
4. 최종 벤더·과금은 **건희·동준**이 샘플 쿼리·쿼터·약관 보고 확정. 기획 제약은 “후보 검색 + 규칙 필터, LLM 좌표 금지”.

참고 자료(조사 시점): 카카오 로컬 문서, 카카오·네이버·구글 지역검색 필드 비교 글, 배민 위치 설계 비공식 서술(라이더 ~5초).

### 10.4 규칙 알고리즘

거리·상태, 종류 필터, 시계, 익음 단계, 채팅 금칙어.
